## 1. 项目现状摘要

### 1.1 已经做到的（不要推倒重来）

当前版本已经是一个**可通关的完整闭环**：挖矿探索 → 波次战斗 → 答题暴击 → 合成/商店 → 金币解锁下一关 → 阳光回流工作台。

| 维度 | 现状 |
|------|------|
| 引擎 | Three.js r147（本地 vendor），固定种子 192×192 高度场世界，16³ 区块面合批渲染，`VIEW_CHUNKS=3`（7×7 区块流式构建/卸载，每帧最多建 1 块） |
| 画质 | 程序化 16px canvas 图集（36 格，移植自 Fable5-mc 思路）+ 顶点 AO + 面明暗 + 顶点色气候染草；无阴影、无抗锯齿（刻意低配保 MuMu WebView） |
| 世界 | 9 种气候（关卡用 6 种）、子生物群系、洞穴、矿石（煤/铁/金/钻）、村庄、池塘、树/花、被动动物、金色单词方块（≤8）、单词闸门（≤3） |
| 战斗 | 近战（8 伤 / 420ms CD）+ 追踪魔法弹（5 伤）；17 种怪物 + 凋零 Boss；答对暴击 ×3、连击≥3 再 ×4；Boss 蓝罩减伤 50%，答对削罩、破罩 8 秒 |
| 学习 | 597 词（core-english-2026.08.15 词包），7 种题型（四选一/听音/看图/填空/拼写/写句/句义），首击必问、Boss 每 3 击一问，错 3 次进硬模式，T 键顽固词施法 |
| 经济 | 合成约 28 配方（随身 2×2 / 合成台 3×3）、商店 4 件商品、卖背包、金币解锁关卡（0/50/150/300/500/800） |
| 工作台 | 同源 localStorage 桥（`workbench-bridge.js`），阳光日上限 80、事件去重、`recordWordAnswer` 回流课程掌握度 |

### 1.2 一句话诊断

**骨架完整、主循环仍是测验**：词牌、五数、未跟读、碎罩规则、题卡麦克风都已有。孩子对准怪物后第一次砍仍会 `openQuiz` 冻住世界。参考新图是**看怪出词、按 V 念、世界不停**。缺口不在「有没有语音函数」，而在入口：开口应打在准星上，而不是打在暂停层里。火/雷/冰技能树新图有，本仓库刻意不做。

## 2. 与参考项目（原版方块传奇）的差距对比

参考项目是 8 岁小朋友 TuTu 用大模型开发的原版「方块传奇」。新附图比旧 `frame_*.jpg` 更清楚：**战斗不暂停**，准星词牌常驻，按 **V** 念出怪物身上的英文。逐条对比：

| # | 原版特性（新图证据） | 本项目现状 | 差距 |
|---|---------------------|-----------|------|
| 1 | **V = Voice Challenge**：帮助写明 `V: Voice Challenge (Say monster name)`；左下麦克风旁实时出 `"pardon"` / `"fast"` / `"ear hundred"` | 题卡里有「说出来」，但出题会**暂停**世界；没有 V 键、没有听写回显 | ★★★ 主循环仍是测验 |
| 2 | **看怪就出词，不弹窗**：`pack / 打包`、`lemon / 柠檬` 挂在怪头顶，怪继续走、玩家继续砍，黄字伤害直接跳 | 有白底词牌，但第一次砍会 `openQuiz` 冻住 | ★★★ 手感相反 |
| 3 | **念对暴击 / 破罩**：不念砍得慢；Boss 蓝球罩，念 `Pardon` 后出大黄字 133 | 点选/拼写/发音都能加伤；拼写或发音可碎罩。孩子先看到的是四选一 | ★★ 规则在，入口错 |
| 4 | **词汇学习五数 + 未跟读**：总词 4326 / 已学 / 未跟读 / 答对 / 答错 | 左下五数已有，「未跟读」已接 shown/spoken | ★ 已对齐外观 |
| 5 | **Listening 条**：右上 `Say: defense break`、词表（schoolbag key fast…）、`My English: N words`、TTS 开关 | 左栏有 Listening / Say:，词表弱、无 TTS 开关 | ★ |
| 6 | **商人有名字**：`Merchant Leo (商人雷奥)` + 头顶黄方块 + `Press F to talk to Merchant Leo` | 有商人、有 F，无英文名、无铭牌 | ★ |
| 7 | **英文操作说明**：整页键位都是英文，点 ? 才展开；T=传送，V=开口 | 有 How to play，未写 V；我们的 T 是打字吟唱，**不要改成传送** | ★★ |
| 8 | **传送选关按年级**：苍翠晶林=三四年级… 花费 1万–10万、还要玩家等级 | 6 关解锁价仍是 0/50/150/300/500/800，词池未按年级 | ★★★ 内容，不改价 |
| 9 | **家长报告**：成就墙、准确率、各年级分布、未跟读 | 无此页；数据可从现有计数拼 | ★★ 单独立项 |
| 10 | **火/雷/冰技能栏 + Skill acquired** | 4 工具 + Q 弹。**本方案不抄技能树**，避免和热键合同冲突 | 刻意不做 |
| 11 | **HP/MP/XP + 金币/攻/防** | 左栏三色条与金币攻防已有 | ★ 已对齐外观 |

**核心洞察（新图修订）**：原版不是「弹出测验再打怪」。它是 **准星上的英文 = 这只怪的弱点**，V 开口或打字打中弱点，世界不停。我们把开口塞进暂停题卡，孩子感觉不到「念了就变强」。下一刀应把 V / 听写回显 / 不停战开口做成主路，四选一只作回退。

## 3. 玩法优化建议

### 3.1 【P0】不停战开口——补上最大差距

识别函数、通道倍率、碎罩、未跟读已经写过。新图证明这些还没变成孩子能用的主路。

**方案**（详见 Phase 5）：

- 普通砍**不再** `openQuiz`。对准即出词牌，世界继续动。
- **V = Voice Challenge**：对 `lookSubject()` 的英文调用现有 `listenOnce` 逻辑，**不打开 quiz-layer**。
- 左下麦克风旁常驻听写引号（新图 `"pardon"` / `"fast"`），对上则 `channel: 'speak'` 暴击；Boss 走 `shieldChipOf('speak')`。
- 听错两次或无麦克风：才暂停出四选一 / 打字。通关不依赖语音。
- 帮助加一行英文：`V — Voice Challenge (say the word on the plaque)`。我们的 T 仍是打字吟唱，不改成参考的传送。

**落点**：`words.js` 的 `shouldAsk`、`game.js` 的 `requestHit` / 新 V 监听、`index.html` 的 `#heard-text`。

### 3.2 【暂缓】职业与技能成长线

新图有 Mage + 火/雷/冰 1–3 栏。**本仓库不抄**：热键合同是 4 工具（剑/斧/镐/铲），Q 已是魔法弹。成长感应先来自「开口变强」，不是再开一套技能树。用户点名再做。

### 3.3 【P1】经济纵深与关卡动机

- **高关卡高收益**：金币/XP 掉落按关卡加权（如 Lv6 掉落 ×3），并在关卡选择界面明示"本关掉落 ×N"，复刻原版"高级关卡怪掉钱多"的动机设计。
- **解锁价格不抄参考**：参考图是 1万–10万 + 玩家等级门。本仓库 `UNLOCK_COST` 锁死 `[0, 50, 150, 300, 500, 800]`，用高关掉落加权制造「下一关更肥」，不要改价。
- **商店扩容**：现在仅 4 件商品。建议按关卡解锁商品档位（皮革→铁→钻石装备、药水、技能卷轴），商人给名字与一句英文台词（"Press F to talk to Merchant Leo" 式提示已是现成学习素材）。
- **修复铁器配方**：`iron_pick/axe/sword` 现在原料还是 cobble+stick，应改为 iron_ingot，同时给冶炼（熔炉已有皮肤数据 `furnace`）一个真实用途：铁矿→熔炉→铁锭→铁器，把"挖矿→冶炼→装备"链条接通。

### 3.4 【P1】单词方块与闸门的学习含金量

- 挖金色单词方块目前**直接记为答对**（`recordWordAnswer(..., true)`），学习含金量为零。改为：挖到后弹轻量跟读/选择卡，答对才 +3 金币 +4 HP，答错进入待复习池。
- 单词闸门可升级为"关卡里的迷你 Boss 门"：连续答对 2 题才开，且题目从**本关错题池**里优先抽。

### 3.5 【P2】世界可玩性

- 现在世界固定 192×192、结构一次生成。短期不必做无限世界（参考2文档也建议不重写），但可以：
  - 给每关加 1-2 个**手工地标**（如樱花关的神社、下界关的堡垒），用现有 `stampWordGates` 的思路盖结构，提升探索记忆点；
  - 洞穴里放**宝箱**（需答题开启），奖励稀有矿/卷轴，让挖矿有目标而不只是路过。

## 4. 学习系统优化建议

### 4.1 【已落地】常驻学习面板（看得见的进步）

左下「词汇学习」五数已对齐新图：**总词 / 已学 / 未跟读 / 答对 / 答错**。下一刀不是再做一块面板，而是让「未跟读」在不停战开口里真的会动。

### 4.2 【P0】错题本与复习循环

现状：错词只影响"硬模式"触发，没有集中复习的地方。建议：

- **错题优先出题**：`nextWord` 抽词时，`mastery` 中 wrong>right 的词权重 ×3（现在只是"未学优先"）。
- **战后复习摊**：`finishLevel` 结算页加"本关错词"列表（词+中文+发音按钮），并给"复习 3 个错词换 5 金币"的按钮——把复习变成赚钱行为。
- **间隔重复**：mastery 里已有次数数据，按"答对次数 0/1/2/3+"分四档，低档词进入下一关词池头部（简单 Leitner 即可，不必上完整 SRS）。

### 4.3 【P1】发音与音标补齐

- catalog 的 `phonetic` 字段全空、audio 仅覆盖约 33/597。短期用 `speechSynthesis` 兜底没问题，但建议：
  - 词卡 UI 预留音标行，词包侧补 `phonetic`（可批量脚本生成 IPA）；
  - 高频词优先补真人/TTS 音频文件（audio 覆盖率从 5% 提到至少前 100 高频词全覆盖）。

### 4.4 【P2】英文化 UI 作为隐性教材

参考原版"问号帮助面板全英文，要认识才行"的巧思：

- 加 "?" 帮助按钮，操作说明用**英文为主 + 中文小字**（新图已有整页英文键位，必须写上 `V — Voice Challenge`）；
- 战斗提示、技能获得、商人对话逐步英文化（"You learned a new word!" / "Shield broken!"），让 UI 文本本身成为可理解输入。

## 5. 美术设计优化建议

结合 `DS-我的世界-3D-参考2.md` 指出的"让画面突然像 MC 的四件事"，经代码核实**结构均已落地**（流式区块、`makeBlockAtlas()` 程序化 16px 图集、顶点 AO、准星描边+裂纹——描边见 `game.js` 的 `EdgesGeometry` 目标框，裂纹见 `CRACK_TILE0` 4 阶段）。

**2026-08-17 修订：** 第 2 条只做到 Fable5 那档 canvas 噪声，不是 mcraft.fun 资源包那种手绘最近邻像素。用户仍觉得不好看，最大缺口回到图集**内容**和概念图/盒模型错位，不是再接世界模型。粒子/天空/动画（下面 §5.1–§5.4）仍做，但排在「真像素图集」之后，见 [美术后续优化方案](./2026-08-17-美术后续优化方案.md) 刀 A→C。

因此不要再补一套 MC 引擎基础，也不要整仓重写；重点是**换图集内容**，然后才是反馈质感与风格统一：

### 5.1 【P1】挖掘与打击的反馈质感

- 准星描边与裂纹已有，缺的是**粒子与声音**：挖掘时在命中点喷 4-8 个方块碎屑小面片；方块破碎/怪物受击配短音效（命中、暴击、破盾、三种材质挖掘声），这是目前"手感"链条上最薄的一环。
- 目标框现为黑色细线（`0x111111`），可在可挖/不可挖时切换颜色（白/红），信息量更足。

### 5.2 【P1】草方块三面贴图与图集细化（四件事之二的收尾）

- 程序化图集已按 Fable5-mc 思路做了 36 格，确认草块是否已区分**顶/侧（带草沿）/底**三张（代码已有"草沿"绘制）；若侧面还是单一贴图，补上草沿过渡。
- 叶子建议改半透明镂空（alphaTest），树冠立刻通透；花/植物用交叉面片（现在是独立 Mesh，见 §6 合批）。

### 5.3 【P1】天空与光照氛围

- 6 张天空 PNG 目前是 `scene.background` 平面纹理，转身时天空不动、易穿帮。低成本升级：贴到一个大 `SphereGeometry`（内面）随相机位置移动，即获得"转头天空跟着转"的效果；或用 Three.js 内置 `Sky` shader（体积小）。
- 补齐 `forest / quarry / astral` 三张天空图（生图管线现成：`assets/generated/ui-refs/` 已有 prompt 工作流，天空图 prompt 可复用 `assets/sky/` 同风格）。
- **昼夜微循环**（可选）：一关内太阳方向缓慢偏移 + 雾色渐变，成本低、氛围收益高；不必做真实昼夜（战斗节奏短）。

### 5.4 【P1】怪物动画与打击感

- 17 种盒模型怪已齐（img2threejs 管线很好），但普遍缺**行走摆动/受击闪白/死亡碎裂**：
  - 行走：四肢按 `sin(t)` 摆动（盒模型 Group 结构现成，每种怪 10 行内搞定）；
  - 受击：材质 emissive 闪白 100ms + 击退位移；
  - 死亡：缩放弹跳消失 + 掉落物品旋转浮动。
- Boss 防护罩视觉对齐参考帧 frame_12：半透明球体 + 菲涅尔边缘发光（`MeshBasicMaterial` + additive 也可近似），破防时变红并加裂纹贴图，比现在更有"破盾"仪式感。

### 5.5 【P2】HUD 视觉统一

- `assets/generated/ui-refs/` 已生成 hud-diegetic / quiz-tablet / look-nametag 三张参考图但**运行时未使用**，目前靠 CSS 仿制。建议把词卡弹窗升级为"石板/木牌"九宫格贴图（参考图切图即可），与体素世界风格更统一。
- 玩家等级徽章、技能栏（§3.2）、学习面板（§4.1）统一橡木金边像素风，参考原版 frame_8 的布局：左上角色状态+小地图、底部中央技能栏、左下学习统计。

## 6. 引擎与性能优化建议

| 优先级 | 问题 | 方案 |
|--------|------|------|
| P0 | `drawMinimap` 每帧扫 192×192（步长 2） | 小地图底图**只画一次**到离屏 canvas（世界不常变），每帧只叠加玩家/怪物标记；方块增删时局部重绘对应像素 |
| P1 | `collectChunkFaces` 每柱扫 y=0…HEIGHT_MAX+16 | 记录每柱实际最高方块 y，扫描到 `maxY+1` 即止；192² 世界重建区块时可省约一半遍历 |
| P1 | 花/植物/装饰各为独立 Mesh | 并入区块合批几何（交叉面片两个 quad），或按区块合并为一个 Mesh；减少数十个 draw call |
| P2 | 树叶/树干在区块边界的重复处理 | 维持现状即可，重构收益低 |
| P2 | 世界数据一次性驻留内存 | 192×192 规模可接受；若未来扩地图，再引入按区块生成（参考 dgreenheck clone 的 worldgen 拆分） |
| — | 不建议做 | InstancedMesh 重写（现有面合批已优于逐块 instancing）、真实阴影（WebView 性能红线）、无限世界（会冲掉关卡设计） |

另外遵循参考2文档的告诫：**不要把"Make a Minecraft clone"式的整体重写提示丢给模型**——现有词卡、bridge、关卡闭环会被冲掉；所有改动应限定在具体文件与函数。

## 7. 移动端体验优化建议

现状：有拖动视角兜底（`dragLook`）、`touch-action:none`、像素比上限 1.5，但**没有虚拟摇杆**，手机上根本无法移动——这是移动端可玩性的第一阻断点。

- 【P0】**虚拟摇杆 + 动作按钮**：左下浮动摇杆控制移动；右下三键（跳 / 攻击 / 魔法）；点击方块=挖，长按=放置（或双按钮切换）。检测 `('ontouchstart' in window)` 时才渲染。
- 【P0】答题弹窗按钮加大到 ≥48px 触控目标，词卡输入题在移动端优先给选择/语音替代打字。
- 【P1】按住屏幕右半拖动视角与摇杆分区（现 `dragLook` 全屏拖动会和摇杆打架）。
- 【P1】MuMu/安卓 WebView 下 `speechSynthesis` 与 `SpeechRecognition` 可用性做能力检测与降级提示。

## 8. 数据与内容优化建议

### 8.1 【P0】词池按难度分级（对齐原版"年级制"）

现状 597 词全 L1，`poolForLevel` 按 CAT_ORDER 排序后**数量均分 6 段**，第 6 关的词不比第 1 关难。参考原版"第一关单词 → 三四年级单词"的递进：

- 短期：利用 catalog 已有但未用的 `difficulty*` / `minecraftBand` 字段排序切池，替换纯数量切分（只改 `words.js` 的 `poolForLevel`，一处改动）；
- 中期：词包扩容并标注 `curriculumLevel` L1-L6（对齐小学 1-6 年级），关卡直接绑级——这也让"花大钱解锁高关"有了"学更难的词"的正当性。

### 8.2 【P1】词包媒体补齐

- image 101/597、audio 33/597、phonetic 0/597。建议排优先级：**高频词 158 个先补齐三件套**（图、音、标），因为 picture/listen 题型只在有媒体的词上才能出，媒体覆盖率直接决定题型多样性。

### 8.3 【P2】怪物词绑定

- 现在词与怪无关联。可给每种怪绑一个主题（zombie→身体词、fox→动物词、witch→表达词），"打什么怪学什么词"增加记忆锚点，也让 17 种怪的美术投资产生学习价值。
