# 语音输入 / 识别轮子调研（2026-08-17）

> 目的：平板开工前先选现成轮子，不自造 ASR。  
> 约束：电脑钥匙只活在 buddy-proxy；游戏页一份 HTML；不写新 localStorage；识别结果仍进现有 `matchHeard`。  
> 本机已有：`POST /v1/stt` + faster-whisper（合成音 `slime` 已通）。真人麦、平板实机未测。

## 1. 我们真正要的不是「通用听写」

孩子按 V 时目标词已锁定（`slime` / `fox`）。问题是「说的是不是这个词」，不是会议转写。

因此：短音频、受限词表、失败就四选一。任何要下 200MB 模型、首次卡 10 秒的方案，都不适合第一关。

## 4. 平板会先踩的坑（和识别引擎无关）

这些比换模型更先挡路：

1. Android 9+ 默认禁 HTTP。平板填 `http://192.168.x.x:4210` 会被 cleartext 拦。要 HTTPS，或工作台 APK 给局域网域名开 `networkSecurityConfig`。
2. WebView 的 `getUserMedia` 必须：`RECORD_AUDIO`、运行时授权、`WebChromeClient.onPermissionRequest` 放行。只改游戏 JS 不够。
3. 浏览器要求安全源。`file://` 或明文 HTTP 上 MediaRecorder 常直接失败。
4. CORS：代理绑 `0.0.0.0` 后必须允许平板 Origin，不能只给 `127.0.0.1`。
5. 安卓 MediaRecorder 编码可能是 `audio/webm` 或 `audio/mp4`，网关已有转码则保持，不要只收一种。

## 5. 裁决（不造轮子）

```text
电脑：Web Speech（Edge 加分）→ 已有 /v1/stt → matchHeard → 四选一
平板家里：同一 VoicePort，只换地址（BUDDY_PROXY_HOST + 电脑 LAN IP）
平板出门 / 网关不通：先试系统 SpeechRecognizer 插件
仍听不到：接现成 sherpa-onnx（Android 或 WASM），文本仍进 matchHeard
禁止：自训模型、APK 打 Python、游戏页塞 Whisper 大包、新 appId
```

T8.4 第一刀只做「局域网复用现有网关」，不嵌入 sherpa。sherpa 是听不到之后的现成备胎，不是现在的新引擎。
