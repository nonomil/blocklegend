# 骑龙大世界方案（2026-08-20）

> 起因：参考小红书笔记 6a7404da《方块传奇 BlockLegend》——骑龙后视野高广、可见山脉与大建筑。
> 对照本项目现状，地形尺度撑不起飞行体验，需系统性改造世界生成。
> 本文档是后续工作的执行方案 + 交接包。

---

## 一、现状硬约束（2026-08-20 实测）

| 参数 | 当前值 | 位置 | 骑龙视角的问题 |
|---|---|---|---|
| 世界边长 | 384 格（24×24 区块） | `data/world-gen.js:10` | 高度 40+ 一眼看到全图与边界 |
| 地形总高 | **HEIGHT_MAX=16** | `data/world-gen.js:11` | 全图高差 ≤16 格，无"山脉"可言 |
| 飞行上限 | 46 | `engine.js` updateMountPhysics | 穿云（42）即触顶 |

| 雾远端 | ~112（按气候 44-142） | `engine.js` applySky | 高空被雾截断，看不到远方轮廓 |

性能红线（MuMu WebView 手机）：每区块一次 draw call、无阴影、pixelRatio≤1.5。

## 二、设计依据：Minecraft 1.18+ 世界生成的核心思想

（注：制定本方案时联网搜索不可用，依据为 MC 公开机制知识）

MC 用**三个正交噪声**决定地形骨架，而非单一高度噪声：

1. **Continentalness（大陆度）**：海洋/平原/内陆山脉的带状划分——山脉成**绵延山系**而非孤峰
2. **Erosion（侵蚀度）**：地形被磨平程度；低侵蚀+高大陆度=尖峭山脊
3. **Peaks & Valleys（脊谷噪声 / ridged noise）**：`1 - |noise*2 - 1|` 折叠产生锐利山脊线

启发：**山脉应带状分布、成体系**；本项目已有 15 个气候区（CLIMATES），可直接当"大陆度"用——每个气候区决定自己的地形骨架与振幅。

## 三、三阶段方案

### Phase 1 — 拔高 + 山系（先做，性价比最高）

改动集中：`rawHeight`（`data/world-gen.js`）+ 三个常量。

1. `HEIGHT_MAX` 16 → **48**
2. 飞行上限 46 → **90**（`engine.js` updateMountPhysics 的 `player.y > 46` 判断）
3. 云层 42 → **72**（`engine.js` ensureCloudLayer 的 CLOUD_Y；穿云体验保留）
4. `rawHeight` 加**脊谷噪声**：
   - 折叠公式 `ridge = 1 - Math.abs(noise * 2 - 1)`，低频（波长 ~100 格）产生**带状山脊**
   - 振幅按气候：snow/volcano/quarry **±20 格**山系；forest/cherry 丘陵 ±6；plains/ocean ±3
   - 保证**村庄/出生点周边平缓**（村庄 stamp 已有 flattenPad，确认覆盖半径够）
5. 高空雾扩展：玩家 y>50 时雾远端 ×1.8（否则高空白茫茫）
6. 摔落伤害检查：骑乘状态是否豁免摔伤（防止孩子骑龙掉进峡谷暴毙）

**有利因素（改动自动适配，无需跟进）**：
- `buildChunkGeometry` 的 `yMax = HEIGHT_MAX + 16` 自动适配
- 碰撞列式（surfaceAt/columnBlockedAt）自动跟随新地形
- 村庄/单词门的 `yAt` 自动落新地表
- `streamChunks` 分块流式已存在

**风险点**：
- 树/建筑 stamp 在陡坡上可能悬空 → 复用 flattenPad 或限制坡度阈值内种树
- 顶点色/AO 在大高差下的观感需截图验收
- MuMu 真机帧率：24×24=576 draw call 不变，但每区块三角形数上升，**必须真机测**

**验收**：
- `node --test "test/*.test.mjs"` 全绿（world-gen 测试有 heights 深比较锚，振幅改动**会改基线**——需同步更新测试的期望结构，不是改逻辑偷偷绕过）
- 浏览器：同 seed 世界截图对比，山系带状可见、村庄平缓、单词门可达
- 真机：骑龙飞行稳态帧率不劣化超过 15%

### Phase 2 — 空中可读的大地标

骑龙核心体验是"从空中找得到东西"。人眼判断尺度靠参照物。

每气候 1 个宏观地标（30+ 格高，飞行导航锚点）：
- forest：巨型树（30-40 格，红杉级）
- volcano：火山锥 + 岩浆口
- snow：雪山堡垒
- cherry：大鸟居/神社
- desert：金字塔
- crystal：水晶尖塔群

实现：world-gen stamp 函数加 `stampLandmark`，确定性放置（rng），world 数据加 `landmarks` 数组供 UI 小地图/罗盘用（可选）。

### Phase 3 — 扩图 + 流式（暂缓，Phase 1 真机通过后再议）

- 384 → 512（32×32 区块 = 1024 draw call 上限，**先真机测 Phase 1 帧率再决定**）
- 或维持 384 但做"无边感"：世界边缘用高山/海洋包裹遮挡边界

## 四、明确不做

- 不上真阴影、bloom（性能红线）
- 不做无限世界/持久化修改区块（存档体系未版本化，见路线图 §11.4）
- 不动 15 气候区划分逻辑（只加振幅参数，保证种子确定性测试可增量更新）

## 六、执行顺序与检查点

```
1. HEIGHT_MAX 48 + 飞行上限 90 + 云层 72（常量三处）→ 浏览器看效果
2. rawHeight 脊谷噪声 + 气候振幅表 → 更新 world-gen 测试基线
3. 高空雾扩展 + 骑乘摔落豁免检查
4. MuMu 真机帧率验收 → 决定是否进 Phase 2
5. Phase 2 地标（每气候 1 个）→ 空中导航验收
```
